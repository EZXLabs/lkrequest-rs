# 文档维护与生成

公开文档由 mdBook 指南站点和 rustdoc API reference 两部分组成。mdBook 负责组织面向任务的说明，rustdoc 负责精确类型、方法、trait、feature 和可编译示例。

## 写作分层

- 用户文档以场景和可执行示例为主：先回答“如何完成任务”，再解释完成任务所需的最少概念；
- 用户概念页只说明对象生命周期、行为边界和选型，不展开 workspace 内部实现；
- 规格与性能页提供可核对的支持列表、验证状态、环境和数据来源；
- 开发者文档着重源码架构、crate 职责、设计不变量、改动归属和验证方法；
- rustdoc 负责精确 API contract，mdBook 不应复制完整方法清单。

每篇用户指南应尽量按“适用场景 → 最小示例 → 常用变体 → 限制与失败处理 → 相关参考”组织。不能要求用户先理解内部 crate 分层，才能完成普通请求。

## 目录约定

| 路径 | 内容 |
|---|---|
| `book.toml` | mdBook 配置、输出目录和公开仓库链接 |
| `docs/SUMMARY.md` | 公开书籍的章节顺序和导航入口 |
| `docs/guides/` | 用户手册：场景、示例与操作步骤 |
| `docs/reference/` | 规格参考：preset 矩阵、能力清单、兼容性、benchmark 现状 |
| `docs/development/` | 开发者手册：crate 架构、实现分析、测试与发布流程 |
| `docs/data/*.toml` | preset、benchmark 和发布产物的机器可读规格源 |
| crate `README.md` | crate 定位、职责边界和最小验证命令 |
| crate rustdoc | API contract、类型语义和可编译示例 |
| `design/` | 内部设计稿、prompt、审计和历史分析，不进入 public snapshot |

新增公开页面后必须显式加入 `docs/SUMMARY.md`。`create-missing = false` 会阻止 mdBook 为错误路径静默创建空文件。

## 本地构建

文档构建基线使用 mdBook `0.5.3`。安装后在仓库根目录执行：

```bash
cargo install mdbook --locked --version 0.5.3
mdbook build
```

生成站点位于 `target/book/`。本地预览：

```bash
mdbook serve --open
```

API reference 单独生成：

```bash
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --all-features --no-deps
```

生成结果位于 `target/doc/`。这两个目录都属于构建产物，不应提交。

## 验证命令

提交文档改动前至少执行：

```bash
mdbook build
mdbook test
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --all-features --no-deps
cargo test --doc --workspace --all-features
```

仅包含示意性、不应执行的 Rust 片段要使用 `rust,ignore`；能够编译但不能在测试中联网运行的片段使用 `rust,no_run`。不要通过关闭全局测试来掩盖单个示例的问题。

## 内容边界

- `docs/` 只描述当前代码和测试能够支持的正式行为。
- `design/` 内容必须重写后才能提升到 `docs/`，不能整篇复制。
- 内部路径、凭据、业务目标、原始抓包和阶段性结论不得进入公开文档。
- 指纹支持列表必须区分直接验证、继承、部分验证和未验证状态。
- benchmark 页面必须保留 workload、环境、原始结果和分位数来源，不能只发布单次排名。
- `lkrequest.h` 是由 cbindgen 在 CI 或发布任务中生成的未跟踪产物。

## 生成内容

后续由规格生成器维护的区块应带固定标记：

```html
<!-- generated by tools/docgen; do not edit -->
```

生成器只能替换明确标记的区块，页面中的解释、限制和用户操作步骤继续由人工维护。源数据与派生 Markdown 必须同时经过一致性检查。

当前机器可读规格包括：

- `docs/data/preset-evidence.toml`：完整 preset、协议层支持与验证证据；
- `docs/data/benchmark-index.toml`：benchmark 数据集状态、环境和公开门槛；
- `docs/data/artifact-schema.toml`：发布产物、签名和验证字段约束。

在 `tools/docgen` 实现前，这些 TOML 与对应 Markdown 仍需人工同步评审。不能把“存在 schema”描述成“页面已经自动生成”。

## CI 产物

GitLab `doc` job 同时生成：

- `target/book/`：mdBook 用户与开发者文档；
- `target/doc/`：workspace rustdoc API reference。

CI 使用与本地相同的 mdBook 版本，并以 `RUSTDOCFLAGS="-D warnings"` 构建所有 feature 的公开 API。文档站点发布可以消费这两个独立产物，但不应在构建过程中修改或提交源文件。
